# 实盘操作问题记录

更新日期：2026-07-20

本文只记录实盘中遇到的问题，不在记录当天直接改代码。晚上统一整理后，再转成需求和开发任务。

## 2026-07-20 交易记录页面问题

来源：实盘录入交易记录时发现。

### 问题 1：价格输入不适合实盘快速记录

当前现象：

- 买入价格/成本价使用了带 `-`、`+` 的数字输入组件。
- 卖出价格也使用了带 `-`、`+` 的数字输入组件。

实盘影响：

- 盘中记录时不需要步进调节。
- `-`、`+` 占空间，容易干扰快速输入。
- 更适合直接键盘输入价格。

晚上待改方向：

- 买入价格/成本价改成普通文本框。
- 卖出价格改成普通文本框。
- 文本框输入后由系统转换为数字。
- 输入为空时按未填写处理。
- 输入非法价格时给出明确提示，不保存脏数据。

### 问题 2：股票代码不应强制手动输入

当前现象：

- 页面要求手动输入股票代码。
- 股票名称和股票代码都需要用户自己填。

实盘影响：

- 盘中更自然的输入方式是直接写股票名称。
- 股票代码手动填容易填错。
- 固定持仓和候选池里的股票，系统本来应该能反查代码。

晚上待改方向：

- 用户优先输入股票名称。
- 系统根据股票名称自动反填股票代码。
- 匹配来源优先级暂定：
  1. 固定持仓映射。
  2. 当日交易池/最终决策。
  3. 卖点信号、午盘验证、次日复盘输出。
  4. 本地板块/股票映射缓存。
- 如果出现重名或找不到，页面再提示用户补充股票代码。
- 股票代码字段可以保留，但不作为第一输入项。

### 问题 3：利润计算缺少印花税

当前现象：

- 页面文案显示手续费按招行证券万2.5、单笔最低 5 元计算。
- 到手利润计算只体现佣金，未明确扣除卖出印花税。

实盘影响：

- A股卖出需要扣印花税。
- 如果不扣印花税，到手利润会偏高。
- 真实交易记录用于后续个性化模型，利润字段必须尽量贴近真实到账。

晚上待改方向：

- 利润计算增加印花税。
- 印花税只在卖出侧计算。
- 默认税率暂按 A股当前常用口径：卖出成交额的 0.05%。
- 费用字段建议拆分：
  - 买入佣金。
  - 卖出佣金。
  - 卖出印花税。
  - 总费用。
  - 到手利润。
  - 到手收益率。
- 页面文案改为：佣金按招行证券万2.5、单笔最低 5 元；卖出另扣印花税。

## 2026-07-20 最终操作表展示问题

来源：查看「明日计划」里的最终操作表时发现。

### 问题 1：固定持仓和候选池混在一起

当前现象：

- 最终操作表里同时展示固定持仓和普通候选。
- 只通过 `固定持仓` 字段用 1/0 区分。

实盘影响：

- 固定持仓是“已有仓位怎么处理”。
- 普通候选是“明天要不要新关注/低吸”。
- 这两类决策目标不同，混在一个表里看起来很乱。

晚上待改方向：

- 将最终操作拆成两个区域：
  - 固定持仓处理。
  - 明日候选池。
- 固定持仓表优先展示：
  - 股票名称。
  - 当前操作。
  - 卖点信号。
  - 买点/风险提示。
  - 简短原因。
- 候选池表优先展示：
  - 股票名称。
  - 最终操作。
  - 规则等级。
  - 融合评分。
  - 简短原因。

### 问题 2：中间模型指标对实盘操作辅助弱

当前现象：

- 最终操作表直接展示：
  - 次日上涨概率。
  - 达到1%概率。
  - 达到2%概率。
  - 止损概率。
  - 风险收益比。

实盘影响：

- 这些字段是模型融合的中间输入，不是最终操作结论。
- 当前样本不足时，概率经常一致，不能有效区分股票。
- 放在主表里会让用户误以为这些数字是强交易信号。
- 真正实盘更需要看“该怎么做”和“为什么这么做”。

解释口径：

- `次日上涨概率`：方向模型判断次日收盘上涨概率；当前如果所有股票都一样，说明模型处在基准概率状态。
- `达到1%概率` / `达到2%概率`：收益目标概率，用来辅助判断潜在空间。
- `止损概率`：触发风控的概率，用来辅助降级。
- `风险收益比`：收益概率和止损风险的比值，是融合评分参考，不应单独作为操作依据。

晚上待改方向：

- 主表默认隐藏这些模型中间指标。
- 将这些字段移到折叠区，命名为“模型依据”或“概率明细”。
- 主表只保留对操作有直接帮助的字段。
- 如果概率全部一致，页面提示“当前模型概率只作观察，不参与强排序”。

### 问题 3：操作解释太长且不够像人话

当前现象：

- 操作解释是规则、概率、板块、风控字段拼接。
- 文案过长，且每一行重复度高。
- 固定持仓里出现“规则未评级(0)”这类对用户没有帮助的说法。

实盘影响：

- 用户无法快速判断为什么减仓、为什么放弃。
- 解释越长，越不适合盘中阅读。

晚上待改方向：

- 操作解释改为更短的“原因标签 + 一句话”。
- 示例：
  - `减仓：市场偏弱，卖点信号触发，先防守。`
  - `放弃：规则等级不足，模型无明显优势。`
  - `只观察：板块一般，概率不支持主动低吸。`
- 固定持仓解释和候选池解释分开：
  - 固定持仓强调持仓处理和风险。
  - 候选池强调是否值得明天关注。

### 问题 4：最终决策报告里的“核心决策”也看不懂

当前现象：

- 展开最终决策报告后，「二、核心决策」继续把固定持仓和普通候选放在同一张表。
- 表格字段包含：
  - 固定持仓。
  - 规则。
  - 融合分。
  - 上涨概率。
  - +1%概率。
  - 止损概率。
  - 最终操作。
  - 理由。
- 这些字段横向很多，移动或窄屏下阅读成本高。
- “规则未评级(0)”“上涨8%”“+1% 78%”“止损22%”这类表达缺少上下文，用户不知道到底该看哪个。

实盘影响：

- 固定持仓需要回答“我手里的票现在怎么处理”。
- 普通候选需要回答“明天哪些票值得看”。
- 两者混在报告里，会让用户误以为它们是同一类决策。
- 核心决策表越长，越不适合盘中或收盘后快速判断。

解释口径：

- `规则`：当前规则系统给出的等级，主要代表技术形态和风控门槛。
- `融合分`：规则、模型、板块、市场、风控加权后的内部评分。
- `上涨概率`：方向模型概率，当前样本不足时可能只是整体基准概率。
- `+1%概率`：达到收益目标的概率，不等于可以买。
- `止损概率`：风险触发概率，用于降级。
- `最终操作`：真正应该优先看的字段。
- `理由`：应该解释最终操作，而不是堆字段。

晚上待改方向：

- 最终决策报告也拆成两个章节：
  - 固定持仓处理。
  - 明日候选池。
- 固定持仓处理只展示用户需要立即看的字段：
  - 股票。
  - 当前操作。
  - 卖点信号。
  - 风险提示。
  - 一句话原因。
- 明日候选池只展示候选决策字段：
  - 股票。
  - 最终操作。
  - 规则等级。
  - 关注优先级。
  - 一句话原因。
- 模型概率和融合分移到折叠的“模型依据/评分明细”章节。
- 报告文案改成更像交易语言，例如：
  - `固定持仓：减仓。原因：市场偏弱，卖点触发，先防守。`
  - `候选池：中国人寿，小仓观察。原因：规则尚可，但模型无明显优势，不追高。`

## 2026-07-20 明日计划与系统次日验证展示问题

来源：查看「明日计划」和「系统次日验证」页面时发现。

### 问题 1：明日计划和系统次日验证应该分开

当前现象：

- 明日计划和系统次日验证在同一条页面工作流里靠得太近。
- 明日计划里还夹杂最终操作、原始报告和复盘相关信息。
- 系统次日验证又展示大量和模型概率相关的字段。

实盘影响：

- 明日计划回答的是：`明天看什么、怎么做`。
- 系统次日验证回答的是：`昨天系统判断得准不准`。
- 两者目标不同，混在一起会打断实盘判断。
- 用户当下想操作时，不需要先看一堆验证字段。

晚上待改方向：

- 明日计划和系统次日验证拆成两个独立 Tab。
- 明日计划只保留对明天操作有用的信息。
- 系统次日验证只做复盘、打标签、模型训练数据沉淀。
- 页面文案明确区分：
  - 明日计划：用于实盘前决策。
  - 系统次日验证：用于事后复盘和训练数据。

### 问题 2：系统次日验证对实际操作的用处需要讲清楚

当前困惑：

- 系统次日验证看起来像又一张交易表，但不知道对今天操作有什么帮助。
- “验证成功”“验证失败/待优化”容易被误解为今天可以买或不能买。

解释口径：

- 系统次日验证不是用来盘中买卖的。
- 它的作用是复盘昨天计划：
  - 昨天给的低吸区间有没有触达。
  - 触达后有没有到 +1% / +2%。
  - 有没有先触发止损。
  - 哪些规则有效，哪些规则要降权。
- 它的结果会进入数据集，给后续模型训练和规则调整用。
- 它不能直接决定今天是否买入，今天操作仍看明日计划、固定持仓和卖点信号。

晚上待改方向：

- 在系统次日验证 Tab 顶部加一句短说明：
  - `这里只看昨天计划准不准，不直接指导今天买卖。`
- 将“验证成功/失败”改成更贴近用途的表达：
  - `计划有效`。
  - `计划待优化`。
  - `未给买点`。
  - `数据不足`。

### 问题 3：系统次日验证表格太复杂

当前现象：

- 验证表展示了：
  - 次日上涨概率。
  - 方向置信度。
  - 达到1%概率。
  - 达到2%概率。
  - 止损概率。
  - 概率信号。
  - 隔夜建议等级。
  - 分时结构标签。
  - 尾盘抢筹标签。
  - 买入参考价。
  - 计划低吸区间等。
- 这些字段很多和用户复盘结论没有直接关系。

实盘影响：

- 一眼看不出昨天计划到底有没有用。
- 概率字段重复出现，容易和明日计划混淆。
- 表格太宽，核心结论被埋掉。

晚上待改方向：

- 系统次日验证主表只保留：
  - 股票名称。
  - 是否固定持仓。
  - 系统验证结果。
  - 是否触达低吸。
  - 是否达到 +1%。
  - 是否触发止损。
  - 复盘结论。
- 概率、分时结构、尾盘标签、买入区间等放进折叠的“验证明细”。
- 增加汇总卡片：
  - 计划有效数量。
  - 待优化数量。
  - 未给买点数量。
  - 固定持仓验证数量。

### 问题 4：系统次日验证也要区分固定持仓和普通候选

当前现象：

- 固定持仓和普通候选在验证成功/失败表里混在一起。

实盘影响：

- 固定持仓复盘重点是持仓处理是否正确。
- 普通候选复盘重点是系统昨天选股是否有效。
- 两者混在一起会干扰判断。

晚上待改方向：

- 系统次日验证拆成两个区域：
  - 固定持仓验证。
  - 候选池验证。
- 固定持仓验证强调：
  - 昨天持仓建议是否有效。
  - 是否应该继续持有、减仓或清仓。
- 候选池验证强调：
  - 昨天计划是否给了买点。
  - 触达后是否达到收益目标。
  - 哪类规则需要优化。

## 2026-07-20 操作话术过复杂问题

来源：实盘查看最终操作、核心决策、系统验证时发现。

### 问题：操作文案不适合紧张实盘

当前现象：

- 页面里的操作解释偏长，像把规则、概率、板块、风控字段拼在一起。
- 表格里的“最终操作”“理由”“操作解释”没有形成固定短句。
- 实盘紧张时，很难快速判断到底是持有、减仓、清仓、观察还是放弃。

实盘影响：

- 用户需要的是直接行动提示，不是模型说明书。
- 文案越长，越容易错过真正的操作重点。
- 同一类结论如果每次话术不一致，会增加理解成本。

晚上待改方向：

- 建立固定操作话术，优先短句。
- 固定持仓和普通候选使用不同话术。
- 主表只展示一句话原因，详细模型依据放进折叠区。
- 系统说明书单独增加“操作话术说明”，让用户知道每个操作词是什么意思。

### 建议固定话术

固定持仓话术：

| 操作 | 页面短句 |
|---|---|
| 继续持有 | `继续持有：暂未触发卖点。` |
| 减仓 | `减仓：风险升高，先降仓位。` |
| 止盈 | `止盈：收益已到，先落袋。` |
| 清仓 | `清仓：卖点触发，先退出。` |
| 止损 | `止损：跌破风控，立即退出。` |

候选池话术：

| 操作 | 页面短句 |
|---|---|
| 优先低吸 | `优先低吸：只等计划买点。` |
| 小仓观察 | `小仓观察：可看，不追。` |
| 只观察 | `只观察：条件不够，先不买。` |
| 放弃 | `放弃：风险不划算。` |

系统验证话术：

| 验证结果 | 页面短句 |
|---|---|
| 计划有效 | `计划有效：给了买点，达到目标。` |
| 计划待优化 | `待优化：给了买点，但收益不足或风险先到。` |
| 未给买点 | `未给买点：计划没有成交机会。` |
| 数据不足 | `数据不足：今天不参与判断。` |

### 系统说明书待补内容

后续需要在系统说明书中单独总结：

- 每个最终操作的含义。
- 固定持仓和候选池的操作区别。
- 哪些话术代表“可以行动”。
- 哪些话术代表“只观察，不行动”。
- 模型概率一致时，为什么不能把概率当成强信号。

## 2026-07-20 模型预测数值一致问题

来源：查看方向预测和收益率预测时发现。

### 问题：方向预测和收益目标预测数值都一样

当前现象：

- 方向预测里每只股票的次日上涨概率相同。
- 方向置信度也相同。
- 收益目标预测里达到 +1%、达到 +2%、止损概率也大量相同。

实盘影响：

- 数值一样就无法排序。
- 无法回答“哪只更强、哪只更值得看”。
- 放在主表中会干扰判断，让用户以为模型给出了有效区分。
- 当前阶段这些概率对实盘操作帮助很弱。

原因判断：

- 当前训练样本仍少。
- 标签分布可能不均衡。
- 特征还不能有效区分不同股票。
- 模型可能回退到整体基准概率。
- 收益目标模型也可能处在基准概率或弱区分状态。

晚上待改方向：

- 页面检测到概率几乎一致时，直接提示：
  - `当前模型未形成有效区分，只作观察。`
- 在这种情况下：
  - 不把方向概率放进主决策表。
  - 不用概率排序候选池。
  - 最终操作优先看规则等级、市场环境、板块状态、卖点信号。
- 模型预测 Tab 中保留概率明细，但增加“模型有效性”提示。
- 明日计划和固定持仓主表只展示：
  - 是否有模型优势：`有优势 / 无明显优势 / 暂不可用`。
- 系统说明书中补充：
  - 当概率一致时，说明模型现在没法帮你选股。
  - 此时不要根据概率做买卖决定。

### 后续优化方向

- v4.1 先做样本质量和覆盖率检查。
- 增加模型有效性指标：
  - 概率唯一值数量。
  - 概率标准差。
  - 排序分化度。
  - 标签正负样本比例。
- 如果模型分化度低，页面自动降级为规则模式。
- 等真实交易记录和样本量上来后，再让模型重新参与强排序。

## 2026-07-20 表格列顺序分散问题

来源：查看 A/B 核心候选等表格时发现。

### 问题：影响操作的列没有放在最前面

当前现象：

- A/B 核心候选表最前面是：
  - 是否已买入。
  - 固定持仓。
  - 置顶原因。
  - 股票代码。
  - 股票名称。
- 真正影响操作的字段，例如最终操作、买卖建议、风险提示、原因，位置不够靠前。
- 模型概率、风险收益比、置信度等中间字段也会挤占主视线。

实盘影响：

- 用户第一眼看不到“这只票要不要做”。
- 盘中紧张时，需要横向找字段，效率低。
- 相似表格的列顺序不统一，会增加学习成本。

晚上待改方向：

- 所有类似决策表统一列顺序。
- 原则是：先操作，再股票，再原因，再状态，最后才是明细。
- 固定持仓、候选池、系统验证分别使用不同优先列。

### 建议统一列顺序

候选池表：

```text
最终操作 -> 股票名称 -> 股票代码 -> 规则等级 -> 关注优先级/融合评分 -> 简短原因 -> 是否已买入 -> 固定持仓 -> 风险提示
```

固定持仓表：

```text
当前操作 -> 股票名称 -> 股票代码 -> 卖点信号 -> 风险提示 -> 买点状态 -> 简短原因 -> 午盘状态 -> 次日验证
```

系统次日验证表：

```text
验证结果 -> 股票名称 -> 股票代码 -> 是否固定持仓 -> 是否触达低吸 -> 是否达到目标 -> 是否触发止损 -> 复盘结论
```

交易记录表：

```text
交易状态 -> 股票名称 -> 交易类型 -> 买入价 -> 卖出价 -> 数量 -> 到手利润 -> 收益率 -> 交易日期 -> 备注
```

模型预测表：

```text
模型状态 -> 股票名称 -> 股票代码 -> 是否有模型优势 -> 次日上涨概率 -> 达到1%概率 -> 止损概率 -> 说明
```

### 页面规则

- 主表不展示超过 8-10 个核心列。
- 模型概率、融合分、置信度等放到折叠明细。
- 每个表第一列必须是“当前最该看的结论”。
- 股票名称要比股票代码更靠前。
- 固定持仓和普通候选不能只靠 1/0 区分，应该分区展示。
