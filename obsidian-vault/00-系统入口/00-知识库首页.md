## 当前版本重点

- 工程基线已完成：入口规范、依赖修复、字段契约、运行追踪和次日验证口径优化。
- v2.4-v3.0 的路线是从规则系统升级为成熟决策系统：规则策略评分 + 机器学习概率 + 预测回顾 + 模型解释。
- v2.5 已单独拆出 [[03-训练数据集与标签系统需求]]，重点是样本库、标签口径、真实交易记录、LLM 辅助标注和 API 成本控制。
- v2.5.1-v2.5.2 合并做页面工作流简化和数据质量优化，人工复盘入口下线，真实复盘统一从交易记录沉淀。
- v2.6 开始训练 [[05-次日涨跌方向模型需求]]，并新增固定持仓样本池：融捷股份、云天化、大为股份、神火股份、天齐锂业。
- v2.7-v2.9 已补齐收益目标概率、概率校准、预测回顾和模型评分。
- v3.0 封板前重点见 [[09-封板差距分析与五步计划]]：先做融合决策，再做单票工作台和路径区间回顾。
- 模型页面使用说明见 [[03-模型训练预测流程]]，尤其是方向置信度一致时的解释。
- 实盘页面简化后的操作话术和使用顺序见 [[04-系统操作说明书]]，页面改动需求见 [[11-实盘页面简化需求]]。
- v3.0 已形成 [[03-项目验收报告]]，后续按 [[04-五阶段宏观开发计划]] 推进。
- 2026-07-22 的“待优化”拆解、模型报告判断和页面修改方案见 [[02-系统复盘与优化方案-2026-07-22]]。
- 2026-07-23 的系统验证复盘、报告口径差异和页面优化见 [[03-系统验证复盘与优化需求-2026-07-23]]。
- 模型评分为空和概率无区分时的强排序保护见 [[04-模型评分为空与强排序保护需求-2026-07-23]]。
- Obsidian 图谱和文件命名规则见 [[05-知识图谱关系索引]]。
- 保持系统定位清晰：本项目是个人交易辅助与复盘工具，不做自动下单。

## 日常使用方式

1. 需求变化记录到 `10-产品需求`。
2. 开发拆解和排期记录到 `20-开发计划`。
3. 每次运行和问题定位记录到 `30-运行记录`。
4. 交易案例、因子复盘和规则修正记录到 `40-交易复盘`。
