# v2.5.1-v2.5.2 工作流简化与数据质量优化需求文档

## 1. 背景

v2.5 已经完成 SQLite 样本库、真实交易记录、标签、特征快照、LLM 辅助标签和质量报告。当前主要问题不是能力缺失，而是页面入口分散，用户打开后像在操作一组脚本，不像在完成一个真实交易日工作流。

因此 v2.5.1 和 v2.5.2 合并做一个小版本：

- v2.5.1：页面工作流简化。
- v2.5.2：数据质量和真实交易记录优化。

本版本不做大规模底层重构，不启动 v2.6 模型训练，先把日常使用链路变清楚。

## 2. 目标

让页面只回答三个问题：

1. 今天能不能做。
2. 明天看哪几只。
3. 做完以后结果怎么样，并怎么沉淀到数据集。

最终页面从“脚本控制台”改成“交易工作台”。

## 3. 决策

### 3.1 页面入口收敛

日常按钮只保留 5 个：

| 按钮 | 真实含义 | 背后脚本 |
|---|---|---|
| 生成明日计划 | 收盘后生成明天交易池和计划 | `market_environment.py`、`strategy_overnight_t.py`、`tail_confirmation.py`、`report_generator.py` |
| 更新卖点信号 | 有持仓时判断卖点 | `sell_signal_engine.py` |
| 午盘验证 | 11:20 后验证上午结构 | `lunch_validator.py` |
| 次日复盘 | 次日收盘后验证昨天计划 | `next_day_validator.py` |
| 保存训练数据 | 把候选、验证、交易记录沉淀到 SQLite | `dataset_builder.py` |

高级工具折叠：

| 按钮 | 使用场景 |
|---|---|
| 单独刷新市场环境 | 只想看市场状态，或主流程前单独检查 |
| 迁移数据库 | 页面数据没刷新、手动改了 output 文件、需要强制同步 SQLite |

### 3.2 Tab 收敛

页面下方只保留 4 个工作区：

| 工作区 | 用途 |
|---|---|
| 今日操作台 | 看市场、记录真实交易、处理卖点、看午盘验证 |
| 明日计划 | 看 A/B 候选、交易计划和板块状态 |
| 复盘验证 | 看次日验证、真实交易复盘和因子表现 |
| 数据与模型 | 看数据集质量、标签覆盖率、LLM 成本和后续模型入口 |

### 3.3 人工复盘入口下线

删除页面上的：

- `生成复盘库` 按钮。
- `人工复盘` Tab。
- `复盘案例` 首页指标。
- 页面读取 `review_cases.jsonl` 作为复盘数据的逻辑。

原因：

- 交易复盘应该来自真实交易记录，而不是另一套人工案例库。
- 后续个性化模型需要学习的是用户真实成交、真实盈亏、是否按计划执行。
- 减少重复记录，避免“交易记录”和“人工复盘案例”两套数据不一致。

保留历史文件，但不再作为页面主入口。

## 4. v2.5.1 页面工作流简化

### 4.1 任务

- 将「一键主流程」改名为「生成明日计划」。
- 将「卖点信号」改名为「更新卖点信号」。
- 将「次日验证」改名为「次日复盘」。
- 将「生成数据集」改名为「保存训练数据」。
- 将「市场环境」和「迁移数据库」移入高级工具折叠区。
- 删除「生成复盘库」按钮。
- 将 9 个 Tab 合并为 4 个工作区。
- 首页指标从「复盘案例」改为「已闭环」。
- 页面说明文案改成贴近日常操作的语言。

### 4.2 验收

- 页面顶部日常按钮不超过 5 个。
- 页面不存在「生成复盘库」按钮。
- 页面不存在「人工复盘」Tab。
- 页面存在 4 个工作区：今日操作台、明日计划、复盘验证、数据与模型。
- 明日计划仍能展示 A/B 候选。
- 今日操作台仍能新增真实交易记录。
- 复盘验证能同时查看系统次日验证和真实交易记录。
- 数据与模型仍能展示数据集质量报告。

## 5. v2.5.2 数据质量和真实交易记录优化

### 5.1 任务

- 真实交易记录成为人工复盘的唯一页面入口。
- 交易记录继续只支持日内T和隔日T。
- 保留买入、卖出、买入并卖出三类方向。
- 继续按招行证券万2.5、单笔最低5元计算手续费、到手利润和收益率。
- 未闭环交易用于提醒，已闭环交易用于真实复盘和后续个性化训练。
- 数据集生成继续读取 SQLite 的 `trade_records`。
- 工作流文档明确：系统验证记录理论计划，交易记录记录真实执行。

### 5.2 验收

- 首页可以看到真实交易记录数量和已闭环数量。
- 页面复盘区不依赖 `review_cases.jsonl`。
- 真实交易记录表可以在今日操作台和复盘验证中查看。
- `python main.py dataset` 后，`trade_records` 仍写入 SQLite。
- 工作流文档不再要求点击生成复盘库。

## 6. 不做事项

本版本不做：

- 不训练 v2.6 模型。
- 不删除历史 `review_cases` 文件。
- 不重构底层策略脚本。
- 不改变现有标签口径。
- 不改变真实交易记录字段结构。

## 7. 新工作流

日常口诀：

> 收盘生成明日计划，盘中记录交易和看卖点，次日做复盘，最后保存训练数据。

按钮顺序：

```text
生成明日计划 -> 明日计划
有持仓 -> 今日操作台 -> 更新卖点信号 / 午盘验证 / 交易记录
第二天 -> 次日复盘 -> 复盘验证 -> 保存训练数据
每周 -> 复盘验证 -> 因子表现 + 真实交易记录
```
