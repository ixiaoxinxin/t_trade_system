# A股隔日T选股系统需求基线 v1.0

基线日期：2026-07-18

说明：用户提供的飞书需求链接当前只能获取到登录/鉴权页面，未能读取文档正文。本基线依据当前仓库代码、配置和输出样例整理，用作后续需求修订的可验证起点。

## 1. 项目定位

本项目是面向个人短线交易复盘与执行纪律的 A股隔日T决策辅助系统。系统不直接下单，不构成投资建议，核心目标是在每天盘中、尾盘和次日复盘时，帮助用户用稳定规则筛选候选、生成交易计划、约束卖点、沉淀因子表现。

## 2. 目标用户

- 使用小资金试盘的个人交易者。
- 偏好隔夜T、尾盘确认、次日快进快出策略。
- 需要把主观经验固化为可重复规则，并持续复盘优化。

## 3. 当前业务目标

- 从 A股全市场中筛出适合隔日T的候选股。
- 按日线结构、分时结构、风险等级和市场环境生成 A/B/C/D 操作等级。
- 生成明日交易池、观察池、放弃池，以及低吸区间、止损价、仓位建议。
- 次日提供午盘验证、卖点信号、最终验证与因子表现统计。
- 将人工复盘案例沉淀为案例库，为后续规则优化提供依据。

## 4. 当前系统范围

### 4.1 已覆盖范围

- 全市场行情抓取：通过新浪、腾讯、东方财富/AKShare 进行股票列表、日线、分钟数据获取。
- 数据缓存：日线缓存复用当天文件；分钟数据仅在 14:55 后允许复用当天缓存。
- 预筛选：排除 ST、北交所；按价格、成交额、涨跌幅进行预过滤。
- 日线评分：依据近5日振幅、成交额、MA5、MA5偏离率、近5日涨幅计算候选评分。
- 风险判断：依据涨幅过热、振幅过高、MA5偏离过大进行风险扣分和风险等级划分。
- 尾盘确认：读取候选股，结合分钟数据计算分时结构、尾盘评分、最终评分和隔夜建议等级。
- 市场环境：读取上证指数、深成指、创业板指；按跌幅阈值划分正常、偏弱、系统风险、情绪冰点。
- 板块资金：通过 AKShare 获取东方财富板块资金流，输出资金流入/回避方向。
- 交易计划：生成明日交易池、观察池、放弃池，提供参考低吸区间、止损价、仓位建议。
- 午盘验证：验证上午冲高、回撤、冲高保持率、上午结构，并生成下午操作建议。
- 卖点信号：基于参考价、当前涨幅、最高涨幅、高点回撤、分时均线和市场环境生成持有、减仓、止盈、清仓、止损信号。
- 次日验证：验证是否达到 1%、是否达到 2%、是否触发 -2% 止损，并按等级和结构统计因子表现。
- 人工复盘案例：维护 jsonl 案例库并输出 Markdown 报告。
- Streamlit 前端：提供一键主流程和分模块执行入口，展示主要输出表格和报告。

### 4.2 暂不覆盖范围

- 自动交易、自动下单、券商账户连接。
- 实盘资金账户同步。
- 多用户权限、云端部署、移动端 App。
- 复杂回测框架和多策略组合调度。
- 对飞书、Notion 等外部知识库的自动同步。

## 5. 主流程

1. 市场环境判断：运行 `market_environment.py`，生成市场环境、风险等级、板块资金方向。
2. 初筛候选：运行 `strategy_overnight_t.py`，生成 `output/overnight_t_candidates.csv`。
3. 尾盘确认：运行 `tail_confirmation.py`，生成 `output/final_watchlist.csv` 和尾盘确认报告。
4. 交易计划：运行 `report_generator.py`，生成 `output/daily_plan.md`。
5. 盘中/次日执行辅助：按需要运行 `lunch_validator.py`、`sell_signal_engine.py`、`next_day_validator.py`。
6. 复盘沉淀：运行 `review_manager.py`、`factor_ranker.py`，更新案例库和因子表现。

## 6. 核心规则基线

### 6.1 资金与交易约束

- 总资金默认：30000 元。
- 单票资金：3000-5000 元。
- 每日最多交易：2 只。
- A股买入按 100 股一手计算。
- 价格区间默认：30-50 元。
- 低吸区间不到，不开仓。
- 跌破止损价，不补仓，先退出。
- 高开冲高优先兑现，不恋战。

### 6.2 候选筛选规则

- 排除 ST。
- 排除北交所。
- 优先保留价格在配置区间内的股票。
- 优先保留成交额满足最低阈值的股票。
- 排除当日涨跌幅异常的股票。
- 候选评分来自日线评分扣除风险扣分。

### 6.3 隔夜等级

- A：优先进入交易池。
- B：可进入交易池，但需结合风险与市场环境。
- C：观察，不主动买入。
- D：放弃。

### 6.4 市场环境风控

- 正常：允许 A/B 低风险票隔夜，按原计划。
- 偏弱：只做 A/B 低风险，仓位减半。
- 系统风险：只允许 A 级低风险，小仓位，单票不超过 2000 元。
- 情绪冰点：不隔夜，原则上空仓。

### 6.5 卖点规则

- 当前涨幅 <= -2%：止损。
- 系统风险/情绪冰点环境下，盈利 1% 以上优先兑现。
- 偏弱市场中，盈利 2% 以上优先兑现。
- 高点回撤超过 2%：清仓。
- 高点回撤超过 1.5%：减仓。
- 冲高保持率低于 30%：清仓。
- 跌破分时均线且仍有利润：减仓。
- A级强结构且保持率高：可继续持有观察二次冲高。

## 8. 前端需求基线

- 使用 Streamlit 作为本地操作台。
- 首页展示系统标题、顶层指标、流程入口和各业务模块。
- 支持一键主流程：市场环境 -> 初筛候选 -> 尾盘确认 -> 交易计划。
- 支持单模块执行：卖点信号、午盘验证、次日验证、复盘案例等。
- 表格展示应优先显示对执行有用字段，原始 Markdown 报告默认折叠。
- 已买入股票需优先展示。

## 9. 当前已知问题

- v2.0 已统一用户可见版本号；因子登记中的历史 `used_in_version` 保留为规则演进记录。
- 依赖文件名为 ` requirements.txt`，前置空格会影响标准安装命令。
- v2.0 已修复 `test_strategy.py` 过期入口，改为调用当前策略入口。
- PushPlus token 在 `sell_signal_engine.py` 中保留既有默认逻辑；本轮按用户决策不修改。
- v2.0 已移除轻量板块/热点标签识别，避免基于股票名称的弱规则误导交易计划。
- 部分功能依赖实时外部行情接口；本轮按用户决策暂不建设离线样本和完整单元测试。
- 多个脚本重复实现字段标准化、股票代码归一化、`safe_float` 等工具函数。
- 成功标准较粗：次日最高达到 1% 且未触发 -2% 即视为验证成功，尚未区分先涨后跌、可执行成交区间和真实执行结果。

## 10. 验收基线

- 在可联网环境中，Streamlit 页面可以启动并展示已有输出文件。
- 一键主流程能顺序执行四个脚本，并生成 `market_environment`、`overnight_t_candidates`、`final_watchlist`、`daily_plan`。
- 若外部行情接口失败，脚本应清晰报错或降级，而不是静默生成误导性结果。
- 所有关键输出中的股票代码保持 6 位字符串格式。
- 交易计划中的交易池数量不超过配置的 `max_trade_count`。
- 情绪冰点环境下交易池为空。
