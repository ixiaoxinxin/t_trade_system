# A股隔日T选股系统需求文档 v2.0

版本日期：2026-07-18

依据：当前仓库需求基线 v1.0。用户提供的飞书链接当前未能读取正文，待获得原文后应补做一次需求差异对齐。

## 1. 版本目标

v2.0 的目标不是扩大策略范围，而是把当前系统整理成稳定、可运行、可复盘、可迭代的个人交易辅助工具。优先解决版本混乱、入口不一致、配置不安全、测试缺失和输出不可追溯问题。

## 2. 版本原则

- 不接入自动下单。
- 不改变既有隔日T策略主线。
- 所有新增规则必须可解释、可配置、可复盘。
- 外部行情异常时允许降级，但不得输出看似正常的错误交易计划。
- 文档、代码入口、输出文件和前端展示必须保持一致。

## 3. 功能需求

### FR-1 版本与入口统一

系统应提供统一版本号 `2.0`，用于前端标题、报告标题、脚本日志和文档。

验收标准：
- 所有主要报告标题显示同一产品版本。
- 每个脚本输出日志包含模块名、产品版本、生成时间。
- 提供统一 CLI 或主入口，支持运行主流程与单模块流程。

建议入口：

```bash
python main.py pipeline
python main.py market
python main.py candidates
python main.py tail
python main.py plan
python main.py lunch
python main.py sell
python main.py next-day
python main.py review
```

### FR-2 依赖与启动规范化

系统应提供标准依赖文件和启动说明。

验收标准：
- 将 ` requirements.txt` 修正为 `requirements.txt`。
- 新增或更新 `README.md`，说明安装、配置、运行、输出位置。
- 提供本地启动命令：`streamlit run app.py`。
- 缺少依赖时，错误信息能指向安装命令。

### FR-3 配置治理

系统按当前决策保留 PushPlus token 既有逻辑，但把可调参数尽量集中到配置。

验收标准：
- 推送开关、止盈止损阈值、最大交易数量、单票金额、价格区间、评分权重均可配置。
- 配置缺失时使用安全默认值，并在日志中提示。
- 提供 `config.example.yaml`。

### FR-4 数据质量与可追溯

系统应记录每次运行的数据源、缓存命中、fallback、失败股票和输入输出路径。

验收标准：
- 主流程结束后生成 `output/run_manifest.json`。
- manifest 包含运行时间、模块版本、配置摘要、输入文件、输出文件、数据源统计、失败列表。
- 当关键数据为空时，中断对应流程并输出明确原因。
- 报告中应标注“数据来源”和“生成时间”。

### FR-5 策略输出一致性

系统应统一候选池、尾盘确认、交易计划、午盘验证、卖点信号和次日验证之间的字段契约。

验收标准：
- 定义 `final_watchlist.csv` 必需字段清单。
- 所有消费 `final_watchlist.csv` 的模块在运行前校验必需字段。
- 缺字段时提供清晰错误信息，并说明由哪个上游脚本生成。
- 股票代码统一为 6 位字符串。

必需字段建议：

| 字段 | 用途 |
|---|---|
| 股票代码 | 跨模块主键 |
| 股票名称 | 展示 |
| 候选评分 | 日线阶段评分 |
| 尾盘评分 | 尾盘确认评分 |
| 最终评分 | 排序依据 |
| 风险等级 | 风控过滤 |
| 隔夜建议等级 | A/B/C/D |
| 隔夜建议说明 | 操作解释 |
| 收盘价或最新收盘价 | 买入参考价 |
| MA5 | 低吸和止损参考 |
| 分时结构标签 | 次日验证统计 |
| 尾盘抢筹标签 | 次日验证统计 |
| 确认日期 | 次日验证定位 |

### FR-6 交易计划可执行性增强

交易计划应更清楚地区分“可买、观察、放弃”，并给出买入前检查清单。

验收标准：
- 明日交易池只包含允许交易的 A/B 标的，且数量不超过 `max_trade_count`。
- 每只交易池股票必须包含低吸区间、止损价、仓位建议、放弃条件。
- 市场环境为系统风险时，只允许 A 级低风险小仓位。
- 市场环境为情绪冰点时，交易池为空。
- 报告中增加“开盘前检查”和“买入后卖点纪律”。

### FR-7 复盘闭环增强

次日验证应从“理论最高空间”升级到“计划可执行性验证”。

验收标准：
- 记录是否触达计划低吸区间。
- 记录触达低吸区间后是否达到 1% 或 2%。
- 区分“未给买点”“给买点但失败”“给买点且成功”“风险先触发”。
- 因子表现统计应包含隔夜等级、分时结构、尾盘抢筹标签、风险等级。
- 复盘案例可关联当日 `final_watchlist` 和 `daily_plan`。

### FR-8 前端工作台整理

Streamlit 前端应围绕每日工作流呈现，减少脚本名对用户的暴露。

验收标准：
- 页面分为：今日准备、尾盘确认、次日执行、复盘沉淀、配置与诊断。
- 每个模块展示最近生成时间和数据状态。
- 主流程按钮应显示每一步成功/失败。
- 原始日志默认折叠，但失败时自动展开错误日志。
- 已买入股票优先展示逻辑保留。

### FR-9 测试保障

当前决策：离线样本和完整单元测试暂不处理，仅修复过期测试入口。

验收标准：
- 修复当前 `test_strategy.py` 入口不一致问题。
- 新增单元测试覆盖：
  - 股票代码归一化。
  - 日线评分。
  - 风险等级。
  - 市场环境分类。
  - 交易池过滤。
  - 卖点信号。
  - 次日验证成功/失败分类。
- 提供一组固定 CSV 样本用于离线测试。

## 4. 非功能需求

- 可维护性：公共工具函数应收敛到共享模块，减少重复实现。
- 可解释性：每个等级、信号和过滤结果都应有原因字段。
- 稳定性：外部接口失败时应可诊断，不应生成误导性空报告。
- 安全性：PushPlus token 本轮按用户决策保留既有逻辑；交易账户密钥不得入库。
- 可移植性：新环境按 README 安装后可运行基础离线测试。

## 5. 约束与假设

- 当前仍以本地单机运行为主。
- 当前仍使用免费/公开行情数据源，数据可靠性不等同专业行情。
- 当前只做 A股短线隔日T辅助，不扩展港股、美股、期货、加密资产。
- 用户最终交易决策由人工确认，系统只提供规则化参考。

## 6. 版本不做事项

- 不做自动下单。
- 不做实盘账户资金同步。
- 不做多用户权限系统。
- 不做云端部署。
- 不做完整历史回测引擎。
- 不接入收费行情源。

## 7. v2.0 版本完成定义

- 能按 README 在新环境安装、启动、运行离线测试。
- 主流程在可联网环境下能生成核心输出。
- 核心可调参数具备配置样例；PushPlus token 本轮按用户决策不修改。
- 版本号、文档、报告、入口命令保持一致。
- 每次运行具备 manifest，可追溯输入、输出和失败原因。
- 复盘结果能回答：当天系统给了什么计划、实际是否给买点、是否达到目标、失败原因是什么。
