# A股隔日T决策系统需求文档 v2.4-v3.0

更新日期：2026-07-19

本文档依据当前 v2.0 工程基线、已实现的 v2.4 板块资金与行业过滤能力，以及用户参考成熟决策系统后整理的产品路线图编写。文档目标是把系统从“规则选股 + 计划复盘工具”逐步升级为“规则评分 + 机器学习概率 + 可解释回顾”的交易决策系统。

### 1.3 当前系统能力

当前系统以规则策略为主，完成了从市场环境、候选扫描、尾盘确认、交易计划、午盘验证、卖点信号到次日复盘的闭环。系统能输出 A/B/C/D 规则等级、低吸区间、止损价、仓位建议、可靠板块状态和验证结果，但尚未具备机器学习概率预测、预测回顾评分和模型解释能力。

## 2. 目标产品架构

### 2.1 总目标

构建一个面向 A股隔日T 的成熟决策系统：

`规则策略评分 + 机器学习涨跌概率 + 预测验证回顾 + 可解释模型`

系统最终不只回答“这只股票是否进入交易池”，还要回答：

- 明天涨跌方向概率是多少。
- 达到 1% 的概率是多少。
- 达到 2% 的概率是多少。
- 先触发止损的概率是多少。
- 所属行业/板块资金状态是否支持。
- 当前市场环境适合什么仓位。
- 最终操作是买入、观察、放弃、减仓、止盈还是止损。
- 昨天的预测准不准，偏差在哪里。

### 2.2 目标输出

| 输出项 | 当前 v2.0 | 目标 v3.0 |
|---|---|---|
| 规则等级 | 已有 A/B/C/D | 保留，并参与融合评分 |
| 次日上涨概率 | 无 | 模型输出 |
| 达到 1% 概率 | 仅次日验证事后统计 | 模型预测 + 事后验证 |
| 达到 2% 概率 | 仅次日验证事后统计 | 模型预测 + 事后验证 |
| 先止损概率 | 仅事后止损判断 | 模型预测 |
| 板块资金状态 | v2.4 已用可靠映射恢复，支持过滤、降权和解释 | v3.0 参与融合风控 |
| 市场环境 | 已有正常/偏弱/系统风险/情绪冰点 | 加入市场 ATR、恐慌程度、强弱市分层 |
| 最终操作 | 已有交易计划和卖点信号 | 规则评分 + 模型概率融合后输出 |

## 3. 决策逻辑

### 3.1 Bluepoint 完美形态决策顺序

后续系统需要把“完美形态”拆成可计算问题：

1. 明天涨跌：输出方向概率和置信度。
2. 怎么走：预测开盘形态和日内路径。
3. 波动区间：预测次日振幅。
4. 跌到哪里：预测最低价区间。
5. 涨到哪里：预测最高价区间。
6. 风险是否划算：计算风险收益比。
7. 模型依据：输出多空信号和关键因子贡献。
8. 昨天预测准确度：计算方向命中、区间覆盖、区间重合和模型评分。

### 3.2 最终操作生成逻辑

最终操作应由三层信号合成：

| 层级 | 输入 | 输出 |
|---|---|---|
| 规则层 | 日线评分、尾盘评分、风险等级、市场环境 | A/B/C/D 和规则建议 |
| 概率层 | 次日方向、达到 1%/2%、先止损概率 | 概率评分和置信度 |
| 风控层 | 市场分层、板块状态、风险收益比、仓位约束 | 最终操作和仓位 |

示例：

- 规则 A + 达到 1% 概率高 + 先止损概率低 + 市场正常：优先低吸。
- 规则 A + 达到 1% 概率一般 + 先止损概率高：观察或降仓。
- 规则 B + 板块强 + 风险收益比好：小仓观察。
- 规则 A/B + 情绪冰点：原则上不隔夜。

## 5. 功能需求

### 5.1 股票预测模块

目标：对单只股票输出次日预测和交易判断。

功能：

- 股票搜索。
- 次日方向预测。
- 方向置信度。
- 开盘形态预测。
- 日内路径预测。
- 振幅预测。
- 高低价格区间预测。
- 多空信号说明。
- 风险收益比。

当前状态：v2.0 只有规则候选、尾盘确认、低吸区间和止损价，没有概率模型。

### 5.2 预测验证模块

目标：记录每次预测并验证预测质量。

功能：

- 预测日期记录。
- 实际涨跌结果。
- 方向命中率。
- 形态命中率。
- 区间覆盖率。
- 区间重合度。
- 模型版本对比。
- 分行业准确率。
- 分市场环境准确率。

当前状态：v2.0 已有次日验证，但还没有预测记录表、模型版本对比、区间重合和分层准确率。

### 5.3 选股模块

目标：从全市场批量预测并生成候选池。

功能：

- 全市场批量预测。
- 置信度排序。
- 流动性过滤。
- 板块资金过滤。
- 风险过滤。
- 行业集中度限制。
- 最终候选池。

当前状态：v2.4 已有全市场规则扫描、流动性过滤、风险过滤、可靠板块过滤、板块降权、行业集中度限制和最终候选池；缺少概率排序和模型推理。

当前状态：v2.0 只有因子表现统计雏形，还没有研究级指标。

## 6. 建模难点

### 6.1 “涨”的定义

模型训练前必须固定标签定义：

- `direction_up`：次日收盘是否上涨。
- `hit_1pct`：次日是否达到 +1%。
- `hit_2pct`：次日是否达到 +2%。
- `stop_first`：是否先触发 -2% 止损。
- `touch_buy_range`：是否触达计划低吸区间。

v2.0 已将验证口径从“最高涨幅”推进到“触达低吸区间后的收益/风险”，后续训练标签应沿用这个更贴近执行的定义。

### 6.2 样本验证规律

建议采用滚动时间序列验证：

- 训练集：过去 2 年。
- 验证集：后续 3 个月。
- 测试集：再后续 1 个月。
- 然后向前滚动。

禁止随机打乱时间序列，否则容易发生未来函数和过拟合。

### 6.3 市场分层

模型必须按市场环境分层观察：

- 强市。
- 震荡。
- 偏弱。
- 系统风险。

当前 v2.0 已有正常、偏弱、系统风险、情绪冰点，后续需要扩展为更适合模型训练的市场 regime 标签。

## 9. 当前决策

- v2.4 前不急于引入模型，先把可靠行业/板块数据和样本标签打牢。
- 不再使用“股票名称关键词”作为板块/热点识别依据。
- 模型预测必须能被事后验证，不能只输出玄学分数。
- 概率输出必须保留校准和回顾机制，否则不能进入最终操作。
- 自动下单仍不进入近期路线。
