## 3. v2.4 板块资金与行业过滤

状态：已实现第一阶段，可进入验收。

### 目标

恢复板块/行业能力，但不再使用股票名称关键词弱识别。板块必须来自可靠数据源或可维护映射，并能参与过滤和风控。

### 任务

- 建立股票代码到行业/板块的映射表。
- 明确行业层级：一级行业、二级行业、概念板块是否分开。
- 计算板块当日涨幅排名。
- 计算板块近5日涨幅排名。
- 计算板块广度：板块内上涨股票比例。
- 计算龙头强度：板块内涨幅前列股票表现。
- 增加行业集中度限制：同一行业/板块最多进入 N 只。
- 在交易计划中展示板块状态，但只展示可靠字段。

### 已完成实现

- 新增 `sector_mapper.py`，从 `output/sector_cache.csv` 读取股票代码到板块的可维护映射。
- 当前层级先采用“所属板块”作为可靠板块字段；一级行业、二级行业、概念板块不混用，后续数据源稳定后再拆分层级。
- 结合 `output/sector_fund_flow.csv` 输出板块涨跌幅、主力净流入、主力净流入占比和当日资金排名。
- 从本地 `cache/daily` 历史日线缓存计算板块近5日平均涨幅和近5日排名。
- 基于映射成分股计算板块广度和龙头涨幅。
- 在 `config.yaml` / `config.example.yaml` 增加 `sector_filter.max_per_sector`、回避状态、谨慎降权分值。
- 在 `report_generator.py` 中加入板块回避过滤、谨慎降权、同板块集中度限制和过滤原因。
- 在 `daily_plan.md` 与 Streamlit 页面中展示可靠板块字段和板块过滤原因。

### 验收

- `final_watchlist.csv` 可包含可靠行业/板块字段。
- 交易池可按板块资金强弱过滤或降权。
- 同一行业集中度限制可配置。
- 报告能解释某只股票因板块弱而降权或放弃。

### 验收状态

- 已满足：`final_watchlist.csv` 可包含 `所属板块`、`板块数据状态`、`板块当日资金排名`、`板块近5日排名`、`板块广度`、`龙头涨幅`。
- 已满足：可靠状态为 `回避` 的标的不进入交易池，`谨慎` 状态按配置降权。
- 已满足：同一板块最多进入 N 只，N 来自 `sector_filter.max_per_sector`。
- 已满足：交易计划表包含 `板块过滤原因`，用于解释降权或转观察原因。

### 风险

- 行业/概念数据源可能不稳定。
- 概念板块容易重叠，必须先定义优先级。

## 4. v2.5 训练数据集与标签系统

详细需求与实施计划见 `docs/03-需求文档/01-训练数据集与标签系统需求.md`，Obsidian 知识库同步文件为 `03-需求文档/01-训练数据集与标签系统需求.md`。

### 目标

建立机器学习前的数据地基，把每一次候选、计划、预测、验证沉淀成可训练样本。

### 数据库决策

v2.5 默认选择 SQLite。原因是免费、轻量、无需服务、Python 标准库即可写入，适合当前个人本地决策系统；默认文件为 `data/dataset/trade_dataset.sqlite3`。后续若样本达到百万级或需要复杂分析查询，再增加 DuckDB；若需要多设备并发或多人协作，再迁移 PostgreSQL。

### 存储迁移决策

从 v2.5 起，页面数据源以 SQLite 为准，CSV/Markdown/JSON 退为兼容导入层。当前版本新增本地迁移能力，把 `output/` 页面输出、报告文档、`cache/daily` 日线缓存、`cache/minute` 分钟缓存、真实交易记录统一迁入 `data/dataset/trade_dataset.sqlite3`。后续每个策略脚本再逐步从“写文件后迁移”改成“直接写 SQLite”。

### 任务

- 设计样本主表：股票代码、预测日期、特征日期、模型版本、规则版本。
- 设计真实交易记录表，只记录日内T和隔日T交易动作。
- 设计标签：
  - 次日收盘是否上涨。
  - 是否触达低吸区间。
  - 触达后是否达到 +1%。
  - 触达后是否达到 +2%。
  - 触达后是否触发 -2%。
  - 次日最高价、最低价、收盘价。
- 建立日线特征：
  - 1/3/5/20 日收益率。
  - MA5/10/20 动量。
  - ATR。
  - 历史波动率。
  - 成交额、换手率、量比。
  - K线实体、上下影线、缺口。
  - 日线特征优先从 `cache/daily/{stock_code}.csv` 计算；缺少可靠数据时字段留空，并在质量报告中展示覆盖率。
- 建立分时特征：
  - 开盘强度。
  - 前15分钟收益和回撤。
  - VWAP 偏离。
  - 冲高回落、探底回升等路径标签。
  - 分时特征优先从 `cache/minute/{stock_code}_1m.csv` 计算；无分钟缓存时不伪造。
- 建立市场环境特征：
  - 市场分层。
  - 市场 ATR。
  - 恐慌程度。
- 建立板块特征：
  - 板块涨幅排名。
  - 板块广度。
  - 龙头强度。
- 建立滚动时间序列切分：
  - 训练：过去 2 年。
  - 验证：后续 3 个月。
  - 测试：再后续 1 个月。
  - 向前滚动。
- 接入大模型 API 辅助标签计算和质检：
  - 优先使用国产大模型 API。
  - 大模型只辅助路径标签、异常解释和冲突复核，不替代确定性行情计算。
  - 支持成本上限、模型供应商切换、prompt 版本追踪和人工复核队列。
  - 增加 `llm_provider_status`，记录供应商、模型、API Key 环境变量名、是否已配置和当前状态。
  - 增加 `sample_limit`，首次接入只跑小样本，避免误开后批量消耗额度。
- 增加页面手动交易记录入口：
  - 支持快速录入股票名称、买入价、卖出价、数量、记录时间、交易类型、执行偏差和备注。
  - 交易类型只保留日内T和隔日T，方向只保留买入、卖出、买入并卖出。
  - 按招行证券万2.5、单笔最低5元自动计算手续费、到手利润和收益率。
  - 不记录情绪状态。
  - 真实交易记录用于后续个性化模型校准。

### 验收

- 可以生成一份结构化训练数据集。
- 每个样本都有清晰特征和标签。
- 标签无未来函数。
- 支持按时间滚动切分。
- 未配置大模型 API Key 时，数据集仍可生成。
- 配置大模型 API Key 后，可生成结构化辅助标签、冲突说明和成本统计。
- 页面可手动新增真实交易记录，并写入 SQLite 的 `trade_records` 表。
- 质量报告可展示核心特征覆盖率、LLM provider 配置状态、调用成本和人工复核数量。

### 大模型接入需要提供的信息

- 供应商选择：建议先从 DeepSeek、豆包、通义中选一个。
- API Key：放入环境变量，例如 `DEEPSEEK_API_KEY`、`DOUBAO_API_KEY`、`DASHSCOPE_API_KEY`、`ZHIPUAI_API_KEY`。
- 开关：本地 `config.yaml` 的 `llm_labeling.enabled` 改为 `true`。
- 成本控制：设置 `max_daily_cost_cny` 和 `sample_limit`，首次建议 3-20 条小样本。

### 风险

- 免费行情源历史分钟数据可能不足。
- 换手率、量比等字段可能需要额外数据源。

## 5. v2.6 次日涨跌分类模型

详细需求与实施计划见 `docs/03-需求文档/03-次日涨跌方向模型需求.md`，Obsidian 知识库同步文件为 `03-需求文档/03-次日涨跌方向模型需求.md`。

### 目标

训练第一个方向分类模型，输出次日上涨概率和方向置信度。

### 固定持仓样本池

本版本先把用户固定持仓纳入每日刷新和置顶展示：

- 融捷股份 `002192`。
- 云天化 `600096`。
- 大为股份 `002213`。
- 神火股份 `000933`。
- 天齐锂业 `002466`。

这些股票固定进入卖点信号、午盘验证和次日复盘。行情缺失时显示待刷新，不直接隐藏；待刷新行不写入有效训练标签。

### 任务

- 使用 LightGBM 建立二分类模型。
- 标签优先定义为 `次日收盘是否上涨`。
- 建立训练、验证、测试脚本。
- 输出评估指标：
  - AUC。
  - PR-AUC。
  - 准确率。
  - 分市场环境命中率。
  - 分行业命中率。
- 将模型预测结果写入预测结果表。
- 在页面「模型训练」增加训练模型按钮，在「模型预测」增加生成预测按钮。
- 在页面核心表展示次日上涨概率、方向置信度和模型方向。

### 验收

- 固定持仓五只股票在卖点、午盘、次日复盘中置顶展示。
- `python main.py holdings-refresh` 可刷新固定持仓日线与分钟数据。
- 单只股票可输出次日上涨概率。
- 全市场候选可按上涨概率排序。
- 模型评估报告可复现。
- 模型版本和训练区间可追溯。
- SQLite 中存在 `model_training_runs` 和 `model_prediction_results`。

### 风险

- 方向预测可能弱于规则评分，不能直接替代规则。
- 样本偏少时容易过拟合。

## 6. v2.7 +1%/+2% 概率模型

详细需求与实施计划见 `docs/03-需求文档/04-收益目标概率模型需求.md`，Obsidian 知识库同步文件为 `03-需求文档/04-收益目标概率模型需求.md`。

状态：已实现第一版，可进入验收。

### 目标

从“涨跌方向”升级到更贴近隔日T执行的收益目标概率。

### 任务

- 训练 `hit_1pct` 模型：触达低吸后达到 +1% 概率。
- 训练 `hit_2pct` 模型：触达低吸后达到 +2% 概率。
- 训练 `stop_first` 或 `hit_stop_loss` 模型：先止损/触发止损概率。
- 计算风险收益概率：
  - `p_hit_1pct - p_stop_loss`
  - `p_hit_2pct - p_stop_loss`
  - 概率风险收益比。
- 将概率输出接入交易计划，但暂不自动替代规则等级。

### 验收

- 交易计划可展示达到 1%、达到 2%、止损概率。
- 概率字段能写入预测记录。
- SQLite 中存在 `profit_probability_training_runs` 和 `profit_probability_predictions`。
- 页面「模型训练」可训练收益目标概率模型。
- 页面「模型预测」可生成收益目标概率排序。
- 复盘报告能统计概率分桶后的实际表现，v2.9 完成完整模型评分。

### 风险

- 日线 OHLC 无法确认高低点先后，路径标签需要分钟数据增强。
- 概率未校准前不能作为最终操作依据。

## 7. v2.8 概率校准与 SHAP 解释

详细需求与实施计划见 `docs/03-需求文档/05-概率校准与模型解释需求.md`，Obsidian 知识库同步文件为 `03-需求文档/05-概率校准与模型解释需求.md`。

状态：已实现轻量校准与解释第一版，可进入验收。

### 目标

让模型输出从“分数”变成更可信的概率，并提供单票解释。

### 任务

- 做概率校准：
  - Platt Scaling。
  - Isotonic Regression。
- 输出校准前后 Brier Score、Calibration Curve。
- 接入 SHAP：
  - 全局特征重要性。
  - 单票多空信号。
  - 正贡献/负贡献因子。
- 在报告中展示模型依据。

### 验收

- 概率校准报告可生成。
- 单只股票可解释为何概率高或低。
- SQLite 中存在 `probability_calibration_curves` 和 `model_explanations`。
- 页面可查看校准后概率和单票多空因素。
- 模型解释不覆盖规则解释，而是并列展示。

### 风险

- SHAP 对非技术用户可能信息过载，需要前端做摘要。

## 8. v2.9 预测回顾与模型评分

详细需求与实施计划见 `docs/03-需求文档/06-预测回顾与模型评分需求.md`，Obsidian 知识库同步文件为 `03-需求文档/06-预测回顾与模型评分需求.md`。

建立预测闭环，判断模型昨天说得准不准、哪个版本更准、在哪些市场环境下失效。

- 建立预测日志：
  - 预测日期。
  - 股票代码。
  - 规则版本。
  - 模型版本。
  - 概率输出。
  - 最终建议。

  - 是否触发止损。
  - 方向命中率。
  - 形态命中率。
  - 区间覆盖率。
  - 区间重合度。
- 建立模型评分：
  - 分模型版本。
  - 分行业。
  - 分市场环境。
  - 分概率区间。
- 监控模型漂移。

### 验收

- 每天预测都能回放。
- 可以比较不同模型版本表现。
- 可以看到模型在哪些行业/市场环境下失效。
- SQLite 中存在 `prediction_review_results` 和 `model_scorecard`。
- 页面可查看 v2.9 回顾报告和模型评分卡。

### 风险

- 如果预测没有稳定落库，回顾会失真。

## 9. v3.0 规则评分 + 模型概率融合

### 目标

把规则等级和模型概率融合，输出最终操作。

### 任务

- 设计融合评分：
  - 规则等级分。
  - 达到 1% 概率。
  - 达到 2% 概率。
  - 先止损概率。
  - 板块资金状态。
  - 市场环境。
  - 风险收益比。
- 输出最终操作：
  - 优先低吸。
  - 小仓观察。
  - 只观察。
  - 放弃。
  - 止盈。
  - 减仓。
  - 清仓。
  - 止损。
- 前端新增决策面板：
  - 规则等级。
  - 模型概率。
  - 多空信号。
  - 风险收益比。
  - 昨日预测回顾。
- 继续保留人工最终确认，不接入自动下单。

### 验收

- 单票可展示完整决策链路。
- 全市场候选可按融合评分排序。
- 最终操作有规则依据和模型依据。
