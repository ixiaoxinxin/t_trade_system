## 1. 结论

当前系统已经完成从“规则选股工具”到“规则 + 概率 + 回顾”的主干升级：

- v2.4：可靠板块资金与行业过滤。
- v2.5：SQLite 样本库、特征、标签、真实交易记录、LLM 辅助质检。
- v2.6：次日涨跌方向模型。
- v2.7：达到 +1%、达到 +2%、触发 -2% 止损概率模型。
- v2.8：概率校准与轻量多空解释。
- v2.9：预测回顾与模型评分卡。

距离成熟决策系统还差最后一层：把这些能力融合成“单票最终判断”和“全市场候选排序”，并把样本质量、路径标签、页面验收体验补齐。v3.0 不建议再扩很多新模型，重点应是融合、稳定和可验收。

## 3. 目前最值得优化的点

### 3.1 先做融合，不急着再加模型

v2.6-v2.9 已经把概率链路打通。下一步最重要不是继续训练更多模型，而是把已有字段转成可执行判断：

- 规则等级是否足够强。
- +1% 概率是否高。
- 止损概率是否低。
- 板块和市场是否支持。
- 真实交易记录是否显示用户对这类票执行效果好。

### 3.2 单票查询要补上

现在页面适合看批量结果，但成熟系统还需要“我现在手里这只票怎么办”的单票工作台。尤其固定持仓已经很明确，应该能一键查看：

- 规则结论。
- 概率结论。
- 板块状态。
- 卖点信号。
- 历史回顾。
- 建议操作。

### 3.3 单票预测不能覆盖全量预测

当前 `model-predict --stock-code` 和 `probability-predict --stock-code` 会覆盖同一个输出 CSV，这是继承 v2.6 的简化设计。后续应拆成：

- 全量预测输出。
- 单票临时预测输出。
- SQLite 历史预测日志。

### 3.4 分钟路径与区间预测是下一块硬骨头

OHLC 只能知道最高和最低，不一定知道先涨后跌还是先跌后涨。成熟系统里的“怎么走、跌到哪里、涨到哪里、区间覆盖率”必须靠分钟路径补齐。

### 3.5 页面先稳定，再简化

当前六 Tab 结构先保留。等 v3.0 融合面板完成后，再把页面压缩成：

- 今日决策。
- 固定持仓。
- 交易记录。
- 模型与复盘。

## 4. v3.0 封板需求

### 4.1 目标

把规则评分、模型概率、板块资金、市场环境和预测回顾融合，输出最终操作。

### 4.2 核心输出

新增 `final_decision_v3.0`：

- 股票代码。
- 股票名称。
- 固定持仓标记。
- 规则等级。
- 规则分。
- 次日上涨概率。
- 达到 +1% 概率。
- 达到 +2% 概率。
- 止损概率。
- 校准后概率。
- 板块状态。
- 市场环境。
- 模型评分参考。
- 融合评分。
- 风险收益比。
- 最终操作。
- 操作解释。

### 4.3 最终操作枚举

买入/持仓侧：

- 优先低吸。
- 小仓观察。
- 只观察。
- 放弃。

卖出/持仓管理侧：

- 继续持有。
- 减仓。
- 止盈。
- 清仓。
- 止损。

### 4.4 融合原则

- 规则等级是入口门槛：D 不因模型概率高而直接买入。
- 止损概率是强风控：止损概率高时优先降级。
- 板块回避是硬约束：可靠板块状态为回避时不得输出优先低吸。
- 市场环境控制仓位：情绪冰点/系统风险时不输出激进建议。
- 模型评分只做权重参考：样本少、评分不稳定时降低模型权重。

## 5. 五个 Commit 开发计划

### Commit 1：融合决策引擎

建议提交名：

```bash
feat: add v3.0 decision fusion engine
```

开发内容：

- 新增 `decision_fusion.py`。
- 读取 `final_watchlist`、v2.6 方向预测、v2.7 概率、v2.8 校准概率、v2.9 评分卡。
- 计算规则分、模型分、风控分、板块分、市场分。
- 输出 `output/final_decision_v3.0.csv`。
- 输出 `output/final_decision_v3.0.md`。
- 写入 SQLite 表 `final_decision_v3`。
- 当前已实现：`python main.py decision-fusion` 会生成融合决策，并保证 D 级、板块回避不被模型概率强行拉成买入。

验收：

- 输出包含融合评分、最终操作、操作解释。

## 6. 推荐执行顺序

1. 先做 Commit 1，因为它把 v2.6-v2.9 的能力真正变成决策。
2. 再做 Commit 2，把最终操作接进交易计划和页面。
3. 然后做 Commit 3，解决单票查询和固定持仓的实战入口。
4. 接着做 Commit 4，补齐路径和区间复盘，减少模型标签误差。
5. 最后做 Commit 5，封板体验、文档和质量门禁。

## 7. 暂不建议立刻做的事

- 不建议马上深度学习。
- 不建议马上复杂多模型融合。
- 不建议为了 SHAP 强行增加依赖，等样本量扩大后再接。
- 不建议现在大改页面结构，先让 v3.0 决策链稳定。
- 不建议接自动下单，继续保持人工确认。

## 8. v3.0 封板验收口径

v3.0 封板时，用户只需要验收五件事：

1. 明日计划能看到最终操作。
2. 固定持仓能看到买点、卖点、概率和最终处理建议。
3. 单票查询能回答“这只票现在怎么看”。
4. 次日复盘能解释模型预测准不准。
5. 交易记录能继续沉淀真实执行结果，用于后续个性化。
