## 1. 总览

当前系统已经从规则驱动的隔日T工具，升级为具备“规则 + 概率 + 校准 + 回顾”的决策系统雏形。成熟目标仍是 v3.0 的规则评分与模型概率融合：用户打开页面后，不只看到候选和概率，还能直接看到最终操作、操作依据和昨日预测表现。

## 2. 已经达标的成熟系统能力

- 规则等级：已有 A/B/C/D、最终评分、风险等级。
- 板块风控：已有可靠板块映射、板块资金状态、板块广度、龙头强度、同板块集中度限制。
- 数据地基：已有 SQLite 样本主表、特征快照、标签表、预测日志、真实交易记录。
- 方向模型：已有 v2.6 次日上涨概率。
- 收益目标概率：已有 v2.7 +1%、+2%、止损概率。
- 校准解释：已有 v2.8 校准报告和轻量解释。
- 预测回顾：已有 v2.9 回顾明细和模型评分卡。
- 固定持仓：融捷股份、云天化、大为股份、神火股份、天齐锂业已进入固定跟踪。

## 3. 仍未达标的成熟系统能力

### 3.1 最终操作还没有统一

目前规则建议、概率、卖点信号、板块状态分散在不同表里。成熟系统需要统一输出：

- 优先低吸。
- 小仓观察。
- 只观察。
- 放弃。
- 继续持有。
- 减仓。
- 止盈。
- 清仓。
- 止损。

### 3.2 单票工作台缺失

用户实际使用时经常不是“看一堆表”，而是问：

```text
这只票现在怎么看？
```

因此需要单票查询入口，把规则、概率、板块、卖点、回顾和最终操作放在一屏。

### 3.3 路径和区间还不够

当前能判断是否触达低吸、是否达到 +1%/+2%、是否触发 -2%，但还没有稳定回答：

- 是先涨后跌还是先跌后涨。
- 预测高低区间是否覆盖真实区间。
- 预测区间和真实区间重合度是多少。
- 低吸区间是否真的有可执行成交机会。

### 3.4 模型样本仍少

当前模型链路能跑通，但样本量不足时会退回基准概率。这个处理是正确的，但也说明现阶段模型更适合辅助排序，不适合直接替代规则。

## 4. 优化优先级

### P0：v3.0 必须做

- 融合决策引擎。
- 最终操作接入交易计划和固定持仓。
- 预测回顾评分反哺融合权重。
- 单票预测不覆盖全量预测。

### P1：v3.0 封板前尽量做

- 单票工作台。
- 区间覆盖率和区间重合度。
- 分钟路径标签。
- 页面质量提示和样本不足提示。

### P2：v3.0 后再做

- 真正 SHAP。
- Platt Scaling / Isotonic Regression。
- 更复杂的多模型融合。
- 深度学习。
- 自动下单。
