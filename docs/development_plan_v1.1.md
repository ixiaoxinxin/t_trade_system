# A股隔日T选股系统 v2.0 开发计划

计划日期：2026-07-18

目标：在不改变策略主线的前提下，把当前系统整理成稳定可运行、可复盘、可继续迭代的 2.0 版本。

## 1. 里程碑总览

| 阶段 | 目标 | 建议工期 | 交付物 |
|---|---:|---:|---|
| M0 | 基线冻结 | 0.5 天 | 需求基线、v2.0 需求、开发计划 |
| M1 | 工程入口与依赖修复 | 1 天 | `requirements.txt`、`README.md`、统一入口 |
| M2 | 配置治理 | 1 天 | 配置样例、配置校验 |
| M3 | 字段契约与运行追踪 | 1.5 天 | 字段校验、`run_manifest.json`、错误诊断 |
| M4 | 交易计划和复盘增强 | 2 天 | 可执行交易计划、计划可执行性验证 |
| M5 | 前端工作台整理 | 1.5 天 | Streamlit 信息架构优化 |
| M6 | 验收与发布 | 0.5 天 | 验收命令、提交记录 |

合计建议：8-9 个工作日。

## 2. 任务拆解

### M0 基线冻结

状态：已完成文档初稿。

任务：
- 整理当前系统需求基线。
- 产出 v2.0 版本需求。
- 制定开发计划。
- 标注飞书需求原文未能访问的风险。

验收：
- `docs/requirements_baseline_v1.0.md`
- `docs/requirements_v1.1.md`（内容按 v2.0 决策更新）
- `docs/development_plan_v1.1.md`（内容按 v2.0 决策更新）

### M1 工程入口与依赖修复

任务：
- 将 ` requirements.txt` 修正为 `requirements.txt`。
- 新增 `README.md`，包含安装、配置、运行、输出、常见问题。
- 新增 `main.py` 统一入口，封装现有脚本。
- 修复或替换 `test_strategy.py` 中过期入口。
- 增加 `--max-count` 或测试模式，便于快速验证候选扫描。

验收：
- `pip install -r requirements.txt` 可使用标准文件名。
- `python main.py --help` 可查看模块命令。
- `python main.py plan` 可单独生成交易计划。
- 过期测试入口不再报 import 错误。

风险：
- 全市场扫描依赖外部行情，不能把联网结果作为唯一验收。

### M2 配置治理

任务：
- 增加 `config.example.yaml`。
- 将卖点阈值、推送开关、市场阈值等硬编码配置迁移到配置文件。
- 增加配置加载与默认值合并工具。
- 敏感配置缺失时只跳过推送，不影响报告生成。

验收：
- PushPlus token 本轮按用户决策不修改。
- PushPlus 既有逻辑保留，卖点报告仍可生成。
- 配置缺字段时不会崩溃，并有清晰提示。

风险：
- PushPlus token 本轮按用户决策不修改。

### M3 字段契约与运行追踪

任务：
- 新增公共字段契约模块，例如 `schemas.py` 或 `contracts.py`。
- 为 `final_watchlist.csv`、`market_environment.json`、`daily_plan.md` 上游输入做校验。
- 新增公共工具函数：`normalize_code`、`safe_float`、CSV 读取、时间格式。
- 新增 `run_manifest.json`，记录运行时间、配置摘要、模块结果、数据源统计、失败列表、输出文件。
- 主流程遇到关键数据为空时停止并报告原因。

验收：
- 缺少 `final_watchlist.csv` 必需字段时，午盘/卖点/次日验证给出明确错误。
- 每次主流程结束后存在 `output/run_manifest.json`。
- manifest 可以定位本次运行使用了哪些输入和输出。

风险：
- 公共工具抽取会触碰多个脚本，需小步提交。

### M4 交易计划和复盘增强

任务：
- 在交易计划中增加开盘前检查、买入放弃条件、买入后卖点纪律。
- 将“低吸区间是否触达”加入次日验证。
- 将验证结果从二元成功升级为分类：
  - 未给买点
  - 给买点且成功
  - 给买点但失败
  - 风险先触发
  - 数据不足
- 因子表现增加风险等级、尾盘抢筹标签维度。
- 人工复盘案例增加可关联字段：计划日期、股票代码、隔夜等级、实际买入、实际卖出、偏离原因。

验收：
- 次日验证报告可以回答“计划是否真的可执行”。
- 因子表现不只按等级/结构统计，还能看风险等级。
- 交易计划里的每只交易池股票都有明确的买入、止损、止盈和放弃条件。

风险：
- 没有真实成交记录时，只能验证“行情是否给买点”，不能验证真实执行。

### M5 前端工作台整理

任务：
- 重组 Streamlit 页面为五个工作区：
  - 今日准备
  - 尾盘确认
  - 次日执行
  - 复盘沉淀
  - 配置与诊断
- 展示每个输出文件的最近生成时间和状态。
- 主流程状态显示成功/失败和失败模块。
- 保留原始 Markdown 折叠展示。
- 增加配置摘要和数据源诊断展示。

验收：
- 用户无需理解脚本名，也能按交易日工作流操作。
- 失败时能在页面看到错误日志。
- 已买入股票仍优先展示。

风险：
- Streamlit 页面过长，需要控制信息密度，避免变成报告堆叠。

### M6 验收与发布

任务：
- 编写 v2.0 发布检查清单。
- 记录一次人工验收结果。

建议测试用例：
- `normalize_code("688006") == "688006"`。
- 正常/偏弱/系统风险/情绪冰点市场环境分类。
- 情绪冰点下交易池为空。
- 系统风险下非 A 级或非低风险不进入交易池。
- 当前涨幅 -2% 以下触发止损。
- 高点回撤超过 2% 触发清仓。
- 次日未触达低吸区间归类为“未给买点”。

验收：
- README 中的快速验证命令可执行。
- v2.0 发布检查清单全部通过。

## 3. 推荐实施顺序

1. 先做 M1，修入口和依赖，让项目可标准启动。
2. 再做 M2，处理敏感配置，避免后续改动继续扩散硬编码。
3. 做 M3，建立字段契约和运行追踪，这是后续稳定性的地基。
4. 做 M4，增强业务价值，把复盘从“看最高涨幅”推进到“看计划是否可执行”。
5. 做 M5，整理前端，让日常使用更顺手。
6. 最后做 M6，用编译检查、命令验收和提交记录封版。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 飞书需求原文未读取 | v1.1 可能与原文有偏差 | 用户提供正文后做差异修订 |
| 外部行情接口不稳定 | 主流程运行失败或输出为空 | 增加 manifest 和失败列表 |
| 策略规则分散 | 修改一处影响多个模块 | 先抽公共契约和工具，再做业务增强 |
| PushPlus token | 本轮按用户决策不修改 | 后续如需安全治理再单独处理 |
| 版本号混乱 | 报告和代码不可追溯 | 统一产品版本常量 |

## 6. 发布建议

v1.1 完成后建议打一个轻量标签：

```bash
git tag v2.0
```

发布说明应包含：
- 本版本修复了哪些可运行性问题。
- 本版本新增了哪些复盘指标。
- 哪些策略规则没有变化。
- 哪些事项留到后续版本。

## 7. 后续候选方向

- 接入更可靠的行业/概念板块映射。
- 引入真实交易记录，区分系统建议与人工执行偏差。
- 增加历史样本回测。
- 支持策略参数对比实验。
- 增加更严格的数据源健康检查。
