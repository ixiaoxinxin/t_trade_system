## 1. 验收结论

v3.0 已达到“规则评分 + 模型概率 + 风控融合 + 页面闭环”的封板目标，可以作为后续 v4.0 开发基线。

本阶段最重要的成果不是模型胜率显著提升，而是把原来分散的能力串成一条可运行的日常决策链：

```text
生成明日计划 -> 查看最终操作 -> 固定持仓处理 -> 单票决策 -> 交易记录 -> 次日复盘 -> 保存训练数据 -> 模型训练/预测
```

当前系统已经能回答三个实盘问题：

- 今天能不能做。
- 明天看哪几只。
- 手里已有股票怎么处理。

## 3. 已完成能力

### 3.1 工程入口

- `main.py` 已成为统一入口。
- 页面支持一键执行明日计划、卖点信号、午盘验证、次日复盘、保存训练数据。
- 页面数据源已以 SQLite 优先，CSV/Markdown/JSON 作为兼容输出。

### 3.2 数据地基

- 已建立 SQLite 样本库。
- 已有样本主表、特征快照、标签快照、预测日志、真实交易记录表。
- 已有数据集生成、时间切分、质量报告和大模型辅助标签框架。
- 未配置或调用失败时，大模型不阻断主流程。

### 3.3 固定持仓

固定持仓已作为独立对象进入系统：

- 融捷股份。
- 云天化。
- 大为股份。
- 神火股份。
- 天齐锂业。

这些股票会在卖点信号、午盘验证、次日复盘和固定持仓页中优先展示。

### 3.4 真实交易记录

- 支持日内T和隔日T。
- 支持买入、卖出、买入并卖出。
- 按招行证券万2.5、单笔最低5元计算手续费。
- 自动计算到手利润和收益率。
- 不再记录情绪状态。

当前真实交易记录为 0，说明系统已经有入口，但还缺真实执行样本。

### 3.5 模型链路

- 方向模型：输出次日上涨概率和方向置信度。
- 收益目标模型：输出达到 +1%、达到 +2%、止损概率。
- 概率校准：输出校准后概率。
- 模型解释：输出轻量多空因素。
- 预测回顾：输出评分卡、路径标签和区间回顾指标。

### 3.6 融合决策

v3.0 已把规则等级、模型概率、收益目标概率、止损概率、板块状态、市场环境和固定持仓状态合并为最终操作。

当前最终操作能输出：

- 放弃。
- 减仓。
- 继续持有、只观察、优先低吸等枚举已在规则中预留。

## 6. 主要不足

### 6.1 样本不足

模型现在能跑通，但样本数和真实交易记录都还少。方向概率一致时，说明模型暂时没有学出个股差异。

### 6.2 分钟路径不足

当前路径回顾已有基础字段，但要真正回答“先涨后跌、先跌后涨、是否先止损”，还需要更稳定的分钟数据和事件序列。

### 6.3 个性化不足

真实交易记录入口已完成，但因为交易记录为 0，还不能形成“你的执行风格”和“你的真实胜率”。

### 6.4 页面仍偏工程化

页面已经比之前清晰，但模型训练、模型预测、最终操作之间仍需要继续收敛成更少的操作入口。

### 6.5 数据源稳定性仍是风险

行情接口、行业映射、分钟数据缓存都可能受外部接口影响。v4.0 应加强缓存、缺失提示和数据源回退。

## 7. 封板判断

v3.0 可以封板。

封板理由：

- 主流程已贯通。
- 页面能支持真实日常使用。
- 固定持仓已进入系统。
- 模型训练和预测链路已打通。
- 最终操作已形成。
- 文档和知识库已同步。

v4.0 不应继续堆零散功能，而应围绕“样本质量、真实交易、路径预测、个性化、页面收敛”推进。
