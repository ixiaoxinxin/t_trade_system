## 1. 背景

模型能力已经从方向预测扩展到收益目标概率、概率校准、模型解释和预测回顾。页面继续按版本号展示后，用户很难判断每天到底要点哪个按钮、看哪个表。

本次需求目标是把模型页面从“版本功能堆叠”改成“真实操作工作流”。

## 2. 目标

- 页面不再展示系统版本号。
- 模型预测标题不展示版本号，只展示业务含义。
- 模型训练 Tab 说明“先保存数据，再训练，再回顾”。
- 模型预测 Tab 说明“先生成概率，再回到最终操作”。
- 当方向概率或置信度全部一致时，页面给出明确解释。
- 形成一篇简单可读的工作流文档，方便日常操作。

## 3. 页面改动

### 3.1 顶部标题

系统标题只显示：

```text
A股隔日T选股系统
```

不显示 `v2.0` 或其他版本号。

### 3.2 模型训练

保留四个动作：

- 训练方向模型。
- 训练收益目标概率模型。
- 生成校准与解释。
- 生成预测回顾。

页面增加一句顺序说明：

```text
保存训练数据 -> 训练方向模型 -> 训练收益目标概率 -> 生成校准与解释 -> 生成预测回顾
```

评估报告默认折叠，避免一打开页面就被长报告占满。

### 3.3 模型预测

保留两个动作：

- 生成方向预测。
- 生成收益目标概率。

表格标题改为业务名：

- 次日上涨概率排序。
- 收益目标概率排序。
- 校准后概率。
- 单票多空因素。
- 模型评分卡。

预测表不默认展示模型版本、校准版本、生成时间等工程字段。版本追踪仍然保留在输出文件和数据库里。

### 3.4 方向置信度一致提示

当页面检测到 `次日上涨概率` 或 `方向置信度` 基本全部一致时，展示解释：

- 当前模型可能处在基准概率状态。
- 样本可能太少或标签太单一。
- 此时概率只做风险提示，不作为个股强弱排序依据。
- 最终仍以规则评分、卖点信号和单票决策为准。

## 5. 验收标准

- 页面标题不再显示 `v2.0`。
- 模型预测表格标题不包含版本号。
- 模型训练报告默认折叠。
- 当方向概率或方向置信度一致时，页面能解释原因。
- README 和 Obsidian 工作流能说明模型训练、模型预测和最终操作的关系。

## 6. 不做范围

- 不修改方向模型训练算法。
- 不删除内部输出文件名中的版本号。
- 不删除数据库里的模型版本追踪字段。
- 不把模型概率直接替代规则评分。
