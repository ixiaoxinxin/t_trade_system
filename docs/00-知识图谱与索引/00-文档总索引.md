# 文档总索引

本地 `docs` 和 Obsidian 使用同一套编号规则。

## 编号规则

1. `01-基线与总计划`：系统基线、总路线、差距、验收和后续宏观计划。
2. `02-每日复盘`：每天盘后复盘和问题记录。
3. `03-需求文档`：从复盘拆出的功能需求。
4. `04-开发计划`：对应需求的开发拆解和验收计划。
5. `05-使用说明`：页面工作流和用户说明书。
6. `06-开发设计`：实现口径、数据流、字段和算法边界。
7. `07-金融操盘实战知识`：A股、黄金、贵金属、AI上游的实战知识和盯盘产品说明。

## 盘后复盘规则

1. 盘后先写 `02-每日复盘/YYYY-MM-DD-复盘主题.md`。
2. 需要改系统时，拆到 `03-需求文档/NN-功能名称需求.md`。
3. 开发前，拆到 `04-开发计划/NN-功能名称开发计划.md`。
4. commit 只提交本次需求和开发计划对应的代码与文档。
